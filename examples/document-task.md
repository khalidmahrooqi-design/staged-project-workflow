# Worked example: revise a project proposal

Request: revise an existing proposal to include an agreed schedule and clearer deliverables. The user has approved the output folder.

1. **Brief:** inspect the source using the permitted reader; confirm the agreed schedule, audience, output format, and acceptance criteria. Ask for missing dates only if the sources do not establish them.
2. **Architecture:** map the executive summary, scope, deliverables, schedule, assumptions, and appendices. Identify which sections change and which sources support the changes.
3. **Plan:** extract relevant source content; revise affected sections; create the output; check content and layout through permitted routes. Each stage has a deliverable and completion evidence.
4. **Execute:** preserve the source, update the draft, and mark each completed step only after checking it.
5. **Verify:** reconcile the schedule and deliverables with the agreed source; inspect the actual output; review relevant conversion or rendering diagnostics. If a permitted tool cannot verify layout, report that limitation.
6. **Close:** deliver the proposal with the checks performed. Correct in-scope issues before closing. If a later appendix needs information that has not been supplied, provide its next steps and identify the missing input without inventing it.

For a one-sentence correction, the same workflow reduces to understanding the requested change, making it, and checking that the meaning is preserved.
